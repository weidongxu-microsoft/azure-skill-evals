# Java criterion occurrence lineage

Comparison: `main` (`8d46011`) versus the preservation-first branch, including
the validated re-audit base and targeted oracle-remediation edits. This document
tracks all 566 original Java criterion occurrences from `main`: 330 shared
`language/*` occurrences and 236 scenario-specific `prompt/*` occurrences.

## Preservation-first findings

- Original occurrences tracked: 566 total = 330 language + 236 prompt.
- Final current criteria: 246 language + 262 prompt = 508 Java panel criteria across 30 scenarios.
- Restored language rows: all 162 formerly `C` rows and all 8 formerly `H` rows are standalone `language/*` criteria with corrected inclusive wording.
- Remaining language removals: 84 high-bar `R` rows only.
- Prompt merges flagged RESTORE/SPLIT in the prior lineage have standalone successors with concrete, non-boilerplate wording. Remaining prompt merges are limited to 6 strict duplicate or inaccurate original rows with proof below.
- Rewritten restored prompt criteria: 115; remaining occurrences of the rejected boilerplate phrases in eval criteria: 0.
- Targeted oracle remediation keeps point counts unchanged while making polling and cleanup language scenario-specific; current-public API wording now admits prompt-required public preview SDK packages.
- No criterion grades MCP calls, skill activation, or tool invocation.

In the disposition column, **restored** describes recovery from the superseded
aggressive re-audit, not a criterion absent from `main`. For a `main`-to-current
comparison, `restored/corrected` means the independent point is preserved with
corrected wording, which is why its point-count effect is zero.

| Ref | Original criterion on `main` | Concise wording |
|---|---|---|
| L1 Dependencies | `language/correct-dependencies-com-azure-not-com-microsoft-azure` | Uses com.azure group ID for all Azure SDK packages. No com.microsoft.azure (legacy SDK) dependencies. Includes azure-identity for authentication. |
| L2 BOM version management | `language/azure-sdk-bom-for-version-management` | Uses azure-sdk-bom in dependencyManagement to manage Azure SDK versions instead of hardcoding individual artifact versions. Dependencies should omit <version> tags when managed by the BOM. |
| L3 Azure imports | `language/correct-imports-no-legacy-no-internal-packages` | All imports use com.azure.* packages. No com.microsoft.azure.* (legacy) or com.azure.*.implementation.* (internal API) imports. |
| L4 Authentication | `language/defaultazurecredential-authentication` | Uses DefaultAzureCredential or another com.azure.identity credential. No hardcoded connection strings, account keys, SAS tokens, or secrets. |
| L5 Client construction | `language/client-builder-pattern` | SDK clients constructed using *ClientBuilder classes with .endpoint() or .vaultUrl() and .credential(). No legacy constructors (CloudStorageAccount, DocumentClient, KeyVaultClient). |
| L6 Current public APIs | `language/no-deprecated-legacy-classes` | No deprecated classes from the old SDK (CloudStorageAccount, CloudBlobClient, DocumentClient, QueueClient, ApplicationTokenCredentials, MSICredentials, ConnectionStringBuilder). |
| L7 Paging/enumeration | `language/pagination-pagediterable-pagedflux` | List/query operations return PagedIterable (sync) or PagedFlux (async). Does not flatten all pages into a raw List or Stream in memory. |
| L8 LRO/polling | `language/lro-pattern-syncpoller-pollerflux` | Long-running operations use SyncPoller (sync) or PollerFlux (async) with begin* method prefix. No Thread.sleep() polling loops. |
| L9 Async/Reactor | `language/async-uses-project-reactor-mono-flux` | Async code uses Project Reactor types (Mono, Flux). Not CompletableFuture (wrong), not RxJava (wrong), not sync wrapped in ExecutorService. No .block() inside async service implementations. |
| L10 Service exceptions | `language/service-specific-exception-handling` | Catches service-specific exceptions (BlobStorageException, CosmosException, ServiceBusException, HttpResponseException) with status code inspection. Not just generic Exception catches. |
| L11 Resource cleanup | `language/try-with-resources-for-clients` | All Azure SDK client instances that implement AutoCloseable are used within try-with-resources blocks or explicitly closed in a finally block. |
